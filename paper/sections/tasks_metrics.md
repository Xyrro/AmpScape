# Tasks, metrics and evaluation protocol

## Problem setting

Each AmpScape sample pairs a resistance raster and a source configuration with the exact output of the reference solver, Circuitscape.jl 5.17.1 or Omniscape.jl 0.6.2 [docs/task_specification.md]. The H×W raster becomes a graph with one node per valid pixel and 8-neighbour edges of Circuitscape's default average conductance, g_ij = (g_i + g_j)/2 (diagonal: /(2·√2)), g = 1/R, with R ≥ 1 and NoData pixels removed from the graph and carried as a separate mask M [docs/task_specification.md]. For an injection vector b the voltages solve L v = b; the stored "current map" is Circuitscape's node current density c_i = max(Σ_j max(i_ji, 0), Σ_j max(i_ij, 0)), which equals ½ Σ_j |i_ij| at non-source nodes and 1 at a unit source or ground [docs/task_specification.md]. The reference linear solver is CHOLMOD in double precision and every sample records its achieved residual ‖L v − b‖₂/‖b‖₂ [docs/task_specification.md]. Pixel size never enters the conductances, so it is metadata only [docs/task_specification.md]. Outputs are stored raw (float32 maps, float64 effective resistances) with no normalisation, clipping or log transform [docs/task_specification.md].

## Task definitions

**Shared inputs.** `inputs/resistance` (H×W float32), `inputs/nodata_mask` (H×W bool), `inputs/covariates` (C×H×W float32, real tiles only), and the task channels `inputs/focal_mask` (H×W int32 labels), `inputs/focal_table` (K×3 int32), `inputs/source_strength` (H×W float32) and `inputs/ground` (H×W int8) [docs/task_specification.md]. Tiers: S 128² (100 m), M 256² (100 m), L 512² (200 m), XL 1024² (500 m), XXL 2048² (1 km) [docs/dataset_card.md].

**T1 — pairwise current mapping.** Circuitscape `pairwise` mode with K ∈ [2, 8] single-pixel focal nodes and all K(K−1)/2 pairs; for pair (i, j), i < j, node i is grounded and 1 A is injected at node j [docs/task_specification.md]. The target is `outputs/cum_current` (H×W float32), the sum over pairs of node current, with focal pixels included (current 1 per pair); for K ≤ 4 the per-pair voltage and current maps (P×H×W, P ≤ 6) and `pair_index` (P×2) are also stored, and `outputs/reff` (K×K float64) is always stored as the T2 effective-resistance target [docs/task_specification.md].

**T1W — wall-to-wall.** Pairwise mode with K = 2 focal *regions*: opposite edge strips of width max(1, H/64) px, two orientations per landscape ("NS": top label 1, bottom 2; "EW": left, right) [docs/task_specification.md]. Repeated labels form one short-circuited region whose every pixel carries the full injected current, so strip pixels are excluded from all metrics; targets are `cum_current` (H×W), `voltage` (1×H×W) and a 2×2 `reff` that is a scalar wall-to-wall conductance metric [docs/task_specification.md].

**T1R — focal regions.** Habitat patches serve as focal regions (configuration `regions`); the target is `cum_current` with the T1 layout, and no per-pair voltages are kept [docs/dataset_card.md][ampscape/models/common.py]. On real tiles the patches are 8-connected WorldCover habitat patches (classes 10, 90, 95: tree cover, herbaceous wetland, mangroves) of at least 50 px, with K ∈ [2, 6] regions whose centroids are at least 16 px apart and patches larger than 2 000 px trimmed to a disc of that size around the centroid [configs/tasks/sources_default.yaml]; on synthetic patch-mosaic landscapes the habitat is the lowest-cost class (R = 1) [DECISIONS.md]. Regions are passed to Circuitscape as repeated labels, i.e. short-circuited supernodes, and landscapes without eligible patches skip the configuration (it is additional to, never a replacement for, point samples) [DECISIONS.md]. Because the WDPA licence is incompatible with CC BY 4.0, protected-area polygons are not used [DECISIONS.md].

**T3 — advanced mode.** Circuitscape `advanced` mode: source raster values are injected currents (`use_unit_currents = False`), grounds are ideal (`use_direct_grounds = True`), `remove_src_or_gnd = keepall` [docs/task_specification.md]. Inputs are R, M, S (ΣS = 1 by construction) and Gnd; sources are a thresholded suitability proxy of R or a random smooth field, grounds one edge, all four edges, or 1–3 random patches, every source connected to a ground [docs/task_specification.md]. Targets: `outputs/current` and `outputs/voltage` (H×W float32, grounds at 0) [docs/task_specification.md].

**T4 — omnidirectional connectivity.** Omniscape grounds, in turn, every pixel with S > `source_threshold` (= 0) on a grid of stride `block_size`, injects current ∝ S from all sources within `radius` px and sums the window maps; flow potential repeats this on a uniform raster and normalized = cumulative / flow potential [docs/task_specification.md]. Sources are `inverse_resistance` suitability above the 0.5 quantile, rescaled to max 1 [docs/t4_fidelity.md]. Targets: `outputs/omniscape/{cum_current, flow_potential, normalized}` (H×W float32; NoData stored as 0 and masked) [docs/task_specification.md]. Production radius / block per tier: S 16 / 1, M 32 / 3, L 64 / 5, XL 128 / 11, XXL 256 / 25 px (block = largest odd integer ≤ radius/10), `correct_artifacts = true`, CHOLMOD window solves [docs/t4_fidelity.md]. Block 1 is exact; larger blocks give the *block-centred* map, a documented approximation of the per-pixel computation [docs/t4_fidelity.md].

**Model inputs and targets.** Baselines receive channel 0 = standardised log-resistance (train-only statistics, 0 at NoData), channel 1 = NoData mask, then the task's source channels (T1: focal mask; T3: source strength scaled by the valid-pixel count plus the ground mask; T4: Omniscape source strength), and predict log10(C + ε·max C) directly under a masked MSE loss [ampscape/models/common.py].

## Metrics

**Transform.** Maps are compared in log10_eps(C) = log10(C + ε·max C), ε = 1e-6 per map; log1p was rejected as scale-dependent, whereas the ε-shifted log is scale-invariant and bounds the range to 6 decades below the maximum [ampscape/metrics/transforms.py].

**Pixel.** MAE in log10-ε space (shift taken from the target), MSE and relative L2 on raw values, with SSIM/PSNR as secondary metrics on the log maps scaled to [0, 1]; NoData and, for T1W, strip pixels are masked [ampscape/metrics/pixel.py]. Log10-ε MAE is the primary metric for current maps [docs/task_specification.md].

**Domain** [ampscape/metrics/domain.py]: top-q % IoU between the q % highest-current valid pixels of prediction and target (q ∈ {1, 5, 10} [docs/TASK_BRIEF.md]; zero-flow pixels never enter the set); corridor Dice between masks above the q-quantile, q = 10 % by default; pinch-point recall, where target pinch points are local maxima of the target (maximum filter of size 2·min_distance + 1 = 7×7 with min_distance = 3 [ampscape/metrics/domain.py]) that lie in the top 5 % of valid pixels, and a hit is a predicted local maximum (also in the predicted top 5 %) within 3 px [ampscape/metrics/domain.py][docs/evaluation.md]; and Spearman rank correlation of valid pixels. These thresholds are conventions, not validated ecological criteria [ampscape/metrics/domain.py][docs/dataset_card.md].

**Effective resistance (T2).** Relative error, log10 MAE, Spearman over the K(K−1)/2 pairs, nearest-neighbour agreement and a symmetry score ‖P − Pᵀ‖/‖P‖ [ampscape/metrics/reff.py].

**Non-source pixels (WP3).** Currents are singular at injection pixels and dominate plain pixel errors, hiding the error on the matrix where corridors and pinch points live [ampscape/metrics/nonsource.py]. Relative L2, log10-ε MAE and top-q IoU are therefore also computed on pixels with zero source strength (T4, no halo) and, for T1/T1W/T1R/T3, outside focal, source and ground pixels plus a 2-px Chebyshev halo; masks come from stored inputs, and the fraction of pixels kept is reported [ampscape/metrics/nonsource.py][docs/REVIEW_ADDENDUM_2026-09.md].

**Physics** [ampscape/metrics/physics.py]: Kirchhoff residual ‖L v − b‖/‖b‖ on the exact graph when a voltage is predicted (collapsed rows for regions); focal-current error |c_pred − c_expected|/c_expected with c_expected the number of pairs the label is in; non-negativity (fraction of negative pixels, most-negative value relative to max); and a throughput error on summed node current, a proxy rather than a conservation law.

**Efficiency and acceleration.** Speed-up = recorded solver wall time (`solve_time_s`) / inference time [ampscape/metrics/efficiency.py][docs/task_specification.md]. The acceleration track counts AMG-preconditioned CG iterations and wall time to the reference tolerance when warm-started from the predicted voltage versus from zero, run in Julia with the same preconditioner and matrix as the stored zero-start baselines (`SolveStats.cg_baseline`, kept for every T1 first pair with K ≤ 4 and every T3 sample) [ampscape/metrics/acceleration.py][docs/task_specification.md].

**T4 against the exact reference.** At M and L, primary T4 metrics are computed against the exact block-1 Omniscape map on `aux/t4_bs1_reference/<tier>` (≈ 1 000 M samples over test_id and every OOD split; 60 at L), with the same metrics against the production target reported as secondary `bc_*`; S needs no reference and XL/XXL are scored against production targets only, with the M/L measurements as the stated fidelity bound [docs/t4_fidelity.md][docs/task_specification.md]. That bound matters: the production M target deviates from the exact map by 3.1 % relative L2 on average (median 2.8 %, worst 25 %), 4–5 % on non-source pixels, while top-5 % IoU and pinch-point recall are both 0.95; at L the mean is 2.8 % (2 of 60 above 5 %) and block 1 costs 22× the production solve [docs/t4_fidelity.md].

## Evaluation protocol

`python scripts/evaluate.py --predictions <dir> --split <name> [--root ... --tier ... --subset ... --out <dir> --acceleration]` writes `results.json` and `results.md` [scripts/evaluate.py]. `--split` takes a comma-separated list; `--acceleration` runs the Julia warm-start evaluation on predicted voltages; `--t4-reference` selects the block-1 reference build (production as `bc_*`); `--t4-blocks` prints block-size baselines scored against the reference beside the model (WP2); `--workers` sets the metric processes [scripts/evaluate.py]. Predictions are framework-agnostic: `<dir>/predictions.h5` holds one group per sample and one subgroup per configuration with `cum_current` (float32 H×W; T1, T1W, T1R, T4), optional `voltage` (float32 H×W or P×H×W, first pair used, for the Kirchhoff residual and acceleration), optional `pairwise_current` (P×H×W), `reff` (float64 K×K; T2), `current` (float32 H×W; T3) and optional `flow_potential`/`normalized` (T4), plus a group attribute `inference_time_s` (per-configuration wall clock including preprocessing) used for the speed-up; `<dir>/meta.json` records model, task, tier, split, notes and seed [ampscape/eval/harness.py][docs/evaluation.md]. Only rows with `qc_pass` in the requested splits are evaluated, samples absent from the predictions file are skipped with the row count reported, samples are processed in sorted order with no randomness, and an oracle scores 0 error / 1.0 on every similarity metric while an all-zero predictor scores rel-L2 = 1 and top-q IoU = 0 [ampscape/eval/harness.py][docs/evaluation.md]. Results are reported on `test_id` and every OOD split, three seeds per configuration (mean ± std), early stopping on `val` [docs/TASK_BRIEF.md]. XL and XXL are held-out-scale tiers for models trained at ≤ L, so their rows in the baselines table come from `scripts/transfer_eval.py`, which runs predictions at batch 1 (the training script likewise forces `bs = 1` for XL/XXL) with inputs normalised by the training tier's statistics, then applies the same harness; the script is resumable, skipping splits whose predictions and metrics already exist [scripts/transfer_eval.py][scripts/train.py].
